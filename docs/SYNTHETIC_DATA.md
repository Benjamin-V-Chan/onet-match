# LLM-generated messy inputs

Real O*NET text is clean and formal, while people write things like *"ran the
robotics club's CAD team"*. To teach and test the matcher on that kind of text,
we paraphrase O*NET content with an LLM into five input types:

| `input_type`  | what it imitates |
|---------------|------------------|
| `description` | informal job descriptions / posting excerpts |
| `experience`  | resume-style experience bullets or first-person sentences |
| `project`     | descriptions of school, work or hobby projects |
| `interest`    | interest / strengths statements that don't name a job |
| `skills`      | skill lists as typed into a profile |

Each snippet is labeled with the occupation whose content it paraphrases.

## Two roles, two different LLMs

| role    | used for | content shown to the LLM | output file |
|---------|----------|--------------------------|-------------|
| `train` | **training only** (bi-encoder and reranker) | title, description, up to 8 **train-split** tasks, top skills and knowledge | `data/matching/synthetic_train.parquet` |
| `eval`  | the held-out `synthetic_test` set | title, description, up to 8 **test-split** tasks, top skills and knowledge | `data/matching/synthetic_eval.parquet` |

The eval set is generated by a **different LLM** from the training set. If the
same model wrote both, a fine-tuned matcher could score well just by learning
that model's phrasing. Using test-split tasks for eval prompts means eval
snippets paraphrase tasks that never appear in training data or in the
occupation documents the models search.

Synthetic data never enters validation or calibration. Temperatures are fitted
on the real validation split only.

## Models used

| role | provider / model | snippets | cost | log |
|------|------------------|----------|------|-----|
| train | Anthropic `claude-opus-5-5`, 3 per type | 14,574 | $23.99 | `outputs/synth/train_claude-opus-5-5.json` |
| eval  | Anthropic `claude-sonnet-5-5`, 1 per type | 4,703 | $6.74 | `outputs/synth/eval_claude-sonnet-5-5.json` |

Both cover all 923 occupations with no failed calls. Snippet counts are after
de-duplication. The 7-occupation pilots cost a further $0.24
(`outputs/synth/pilot_*.json`). The two roles use different Claude models, not
different vendors.

Token usage and cost are recorded per call in the raw JSONL log and summarized in
`outputs/synth/*.json`. That summary is the source for the cost numbers above.

## Prompt (version `v1`)

There is one call per occupation and it requests all five types at once
(`--per-type` snippets each, default 3). The output is constrained with a JSON
schema: an object with one string array per input type. Sampling parameters are
left at their defaults. The source of truth is `onet_analysis/matching/synth.py`
(`SYSTEM_PROMPT`, `INPUT_TYPES`, `render_prompt`). `tests/test_matching_docs.py`
checks that this page stays in sync with that code.

**System prompt**

> You write realistic, varied, human-sounding text snippets that people type into career and hiring tools. Your snippets are used to train and test a system that maps free text to occupations, so they must sound like real people (students, career changers, recruiters, experienced workers) rather than like an occupational database. Paraphrase in everyday language; never copy the reference material verbatim.

**User prompt template**

```text
Reference occupation (for you only — the writers must not name it):
Title: {title}
What it does: {description}
Example tasks:
- {task 1}
- ...
Important skills and knowledge: {skill 1}, {skill 2}, ...

Write {n} distinct snippet(s) for EACH of these input types:
1. "description": an informal job description or job-posting excerpt, as a recruiter, hiring manager or small-business owner might write it (2-5 sentences; may mention perks, schedule, abbreviations or small typos; may use an informal or company-specific job title, but not the exact official occupation title)
2. "experience": a person describing their own past work, volunteer, military or school experience — resume-style bullets or one or two first-person sentences (e.g. "ran the robotics club's CAD team")
3. "project": a description of a specific project someone did at school, at work or as a hobby (1-3 sentences, first or third person)
4. "interest": an interests or strengths statement from a student or career changer that points toward this kind of work without naming any job (e.g. "I love drawing and figuring out how machines work")
5. "skills": a list of 4-10 skills, tools or certifications as someone might type them into a profile (comma-, slash- or newline-separated; mixed capitalisation is fine)

Rules:
- Each snippet should be most consistent with the reference occupation, but realistic: vary voice, age, education level, length and specificity; some can be vague, terse or slightly off-topic, like real input.
- Do not use the words of the official title "{title}" (the "description" type may use a different, informal job title).
- Paraphrase; do not copy task statements.
- Return JSON only, with one key per input type, each mapping to a list of {n} string(s).
```

## Post-processing

- Exact duplicates are dropped after lowercasing and collapsing whitespace.
- `title_leak` flags snippets other than `description` that contain every
  content word of the official title. They are kept, and their rate is
  reported in the pilot and generation summaries.
- Failed calls are logged with `ok: false` and retried on the next run. Runs
  are resumable, and occupations already generated are skipped.

## Reproducing

```bash
export ANTHROPIC_API_KEY=...          # or OPENAI_API_KEY / --api-key-env for other providers
# 1. pilots (7 occupations each): check cost and quality
onet-analyze matching synth --role train --provider anthropic --model claude-opus-5-5 --pilot 7
onet-analyze matching synth --role eval  --provider anthropic --model claude-sonnet-5-5 --pilot 7 --per-type 1
# 2. full runs (the ones behind the saved results)
onet-analyze matching synth --role train --provider anthropic --model claude-opus-5-5
onet-analyze matching synth --role eval  --provider anthropic --model claude-sonnet-5-5 --per-type 1
# a non-Claude eval model works too:
#   --provider openai-compatible --model <model> --price-in <usd/Mtok> --price-out <usd/Mtok>
```
